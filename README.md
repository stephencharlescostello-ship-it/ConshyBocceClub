# CBC Shuffle

The Conshohocken Bocce Club shuffleboard league app: live scoring, standings, schedule, trash talk, events, subs, playoffs and an admin console. An installable PWA built with Next.js 16, TypeScript, Tailwind and Supabase, deployed on Vercel.

- **Players:** scan the table QR → keep score with big +1/+2/+3/Hanger buttons → the other captain confirms → standings update instantly. Works offline at the bar and syncs when the signal returns.
- **Commissioner:** seasons, teams, rosters, round-robin schedule generator, disputes, overrides, events, announcements, moderation, dues, CSV import/export, QR posters, audit log.

## Local development

Requirements: Node 20+, Docker (Docker Desktop, OrbStack or Colima), and the [Supabase CLI](https://supabase.com/docs/guides/cli).

```bash
npm install
cp .env.example .env.local        # the defaults in .env.local already match `supabase start`
npm run db:start                  # Postgres, Auth, Realtime, Storage, Mailpit on localhost
npm run db:reset                  # applies migrations and loads the seed (half-played season, chat, events)
npm run dev                       # http://localhost:3000
```

Signing in locally: the sign-in page emails a magic link to **Mailpit** at http://localhost:54324. Or open http://localhost:3000/dev/login to pick any seeded account (admin: `commissioner@example.com`). Dev login only exists when `NODE_ENV=development` and `ALLOW_DEV_LOGIN=true`.

### Scripts

| Script | Purpose |
| --- | --- |
| `npm run dev` / `build` / `start` | Next.js |
| `npm run typecheck` / `lint` | TypeScript strict + ESLint |
| `npm test` | Vitest unit tests (scoring engine, standings/tiebreakers, schedule generator, playoff seeding, offline queue, bot, CSV import) |
| `npm run test:rls` | RLS/RPC integration tests against the local Supabase stack |
| `npm run test:e2e` | Playwright end-to-end flows at iPhone 15 and Pixel 7 viewports |
| `npm run screenshots` | Shoots every screen, dark and light, both devices → `screenshots/` |
| `npm run lighthouse` | Lighthouse mobile audit of a production build → `lighthouse/` |
| `npm run db:types` | Regenerate `src/lib/supabase/database.types.ts` after a migration |
| `npm run posters` | Build `docs/qr-posters.pdf` and `docs/player-quickstart.pdf` |
| `npm run zip` | Zip the repository (without node_modules) to `dist/` |

## Project layout

```
supabase/migrations/   schema, RPCs, RLS, realtime + storage policies
supabase/seed.sql      generated by scripts/generate-seed.ts (imports data/s26/scores.csv)
src/lib/engine/        pure TypeScript: format, scoring, standings, schedule, playoffs, offline queue, bot, power rankings
src/lib/import/        CSV parsing, Google-Form result pairing, import engine
src/lib/actions/       server actions (validated with zod; writes go through RLS or SECURITY DEFINER RPCs)
src/lib/server/        notifications (web-push + inbox) and the post-confirmation pipeline (bot, badges, awards)
src/app/(app)/         player-facing screens (tabbed shell)
src/app/(admin)/       admin console
src/app/api/           ICS feeds, share cards, cron, push subscribe, exports, posters, health
public/sw.js           service worker: app-shell cache, offline page, push
tests/unit, tests/rls, tests/e2e, tests/screens
```

## Branding

The header uses a text wordmark plus a generic shuffleboard mark (`src/components/ui/logo.tsx`). To use the club's real logo, drop it at `public/branding/logo.png` (square, ≥512px) and replace `ShuffleMark` in `logo.tsx` with `<img src="/branding/logo.png" …>`; the PWA icons at `/icons/*` are rendered from the same component. Every color is a token in `src/app/globals.css`.

## Capacitor (optional app-store wrapper)

`capacitor.config.ts` points the native shell at the deployed URL. `npm i @capacitor/ios @capacitor/android && npx cap add ios && npx cap add android && npx cap sync`.
